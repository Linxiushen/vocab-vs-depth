# 第一课：一次预训练到底发生了什么

我们已经有一个从随机权重开始训练过的 30M 模型。这个阶段的任务是预测下一个
token。预训练文件虽然包含问答文本，但训练时没有专门只对 assistant 回答算损失；
它仍是对整段文本做 next-token prediction。SFT 是后面的另一阶段。

## 用一条样本走完数据流

在项目根目录运行以下命令，看自己的 tokenizer 怎样切词：

```bash
.venv/bin/python -c 'from transformers import AutoTokenizer; t=AutoTokenizer.from_pretrained("minimind/model"); s="学习语言模型需要数据"; ids=t.encode(s,add_special_tokens=False); print(ids); print([t.decode([i]) for i in ids])'
```

1. `PretrainDataset.__getitem__` 读 JSONL 的 `text` 字段，把文字变成整数 ID。
2. 在正文前加 BOS、后加 EOS，截断并 pad 到 512 个位置。
3. `labels` 先复制输入，pad 对应的 label 改为 `-100`，表示不参与交叉熵。
4. 模型输出每个位置对 6,400 个 token 的预测分数，形状是 `[batch, 512, 6400]`。
5. `logits[:, :-1]` 对齐 `labels[:, 1:]`。位置 t 预测的是 t+1，不能把两边同时前移。
6. 交叉熵衡量正确下一个 token 得到的概率。反向传播计算每个参数该怎样调整。

相关代码：`minimind/dataset/lm_dataset.py` 的 `PretrainDataset`，
`minimind/model/model_minimind.py` 的 `MiniMindForCausalLM.forward`。

## 模型内部的四段计算

| 部分 | 输入变成什么 | 本次 30M 配置 |
|---|---|---|
| Embedding | token ID -> 向量 | 6,400 个词条，每个 512 维 |
| Transformer | 结合前文更新每个位置的向量 | 8 层，因果注意力、RoPE、RMSNorm、SwiGLU |
| 输出投影 | 向量 -> 每个 token 的分数 | 与输入 embedding 共享参数 |
| Cross-entropy | 分数 + 正确答案 -> 标量 loss | 忽略 label=-100 的位置 |

词表更大会增大输入 embedding 和输出分类的计算；因为这里共享权重，参数只算一份。
多一层则增加上下文处理能力和计算。我们的 64M 课题比较这两种预算分配。

## 四个容易混淆的计数

旧训练的 batch=8、accumulation=4、sequence length=512、数据=40,000 条：

- micro-batch 数是 40,000 / 8 = 5,000，也是原脚本日志里的 step。
- optimizer update 数是 5,000 / 4 = 1,250。每四次反向传播更新一次权重。
- 前向处理位置数是 40,000 × 512 = 20,480,000，里面有 padding。
- 真正参与监督的是正文的非 pad token 和 EOS，精确数见 `results/smoke-audit.json`。

padding 不计入 loss，并不代表密集张量计算自动跳过了这些位置。
梯度累积模拟较大的批量，但逐 micro-batch 平均 loss 与按全部有效 token 加权平均
也不完全相同，尤其当样本长度差异大时。

## 怎么知道模型学到了东西

单条日志是某个 batch 的损失，不能用相邻两点的升降解释学习率是否有效。
先在固定、未见过的数据上评测，再和随机初始化模型比较，才有清晰的参照。

`ln(6400)` 是均匀概率预测器的交叉熵。实际随机网络的输出并不完全均匀，
所以它不必严格等于这个数字。unigram 基线也应该从训练数据估计字频、在验证数据
上计算交叉熵；不能直接把另一份数据的经验熵当成严格的过线标准。

跨词表比较时，用同一批完整原文的 BPB：

```text
BPB = 全部正文 token 的负对数似然之和 / (ln(2) × 原文 UTF-8 字节数)
```

新的评测脚本把长文分块，每块加 BOS，所有正文 token 恰好计分一次。
块长决定上下文条件，因此报告分数时要同时记录分块协议。

## 亲手做的三个小实验

1. 更换上面的中文句子，观察常用词、数字、生僻字的切分。用
   `lab/tokenizers/bpe_16384` 替换路径，再比较 ID 数量。不同词表的相同 ID 没有相同含义。
2. 打开 `model_minimind.py` 的 loss 计算，把 `logits[..., :-1]` 与
   `labels[..., 1:]` 在纸上对齐前三个位置，说明每个位置在预测什么。
3. 运行 `.venv/bin/python lab/sample_pretrain.py --prompt "学习语言模型需要"`，
   查看自己训练的模型续写。输出可能重复或不准确，这是当前小规模训练的实际表现。

这三个实验不修改现有权重。完成后，再进入 64M 两组正式训练和同协议评测。
