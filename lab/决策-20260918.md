## 一、公平对比协议（最终版：`independent_pack_equal_compute_v3`）

### 1.1 选定方案与否决理由

| 候选 | 判定 | 理由 |
|---|---|---|
| 各臂独立 packing（每臂各自填满 511 token） | **采纳** | 两臂 padding 均为 0；每 microbatch 有效 token 数恒定，上游 `loss/accumulation_steps` 的归一化自动变精确；实测相对共同块方案丢掉的控制只有 0.07% 的 token 不对称 |
| A 驱动共同文本分块（方案一 v3） | 否决 | B 每块只有 433 个真 token、79 个 padding，把「每字节少花 15.5% position」这个**被测机制**转化成浪费。且「等 token 从中间 checkpoint 免费拿」不成立：A@s vs B@1.184s 给了 B 多 18.4% 的算力，与「B 自行 packing、同墙钟多读 18.4% 原文」是两个不同实验 |
| 定长字节块 | 否决 | 实测 budget=1850 字节时已有 16.2% 的块超 511 A-token；要保证不溢出需约 40% padding |
| δ\* 实用等价带（方案二） | 否决 | 系数算错（应 log₂(1.1842)/2 = 0.122，方案用 0.104），且用 L2→L4 平均斜率冒充局部斜率。改为直接报 ΔBPB ± 95% CI 与达成的 MDE |
| 中途 checkpoint 做等算力/等字节结论点 | 否决 | 未退火，系统性劣于同预算完整退火模型。改为每个结论点一个独立完整退火 run（在 4090 上一个 run ≈ ¥3，比实现 WSD-S 分叉便宜） |
| 全局 lr 网格探针 | 否决为调参手段 | 支撑它的文献结论（arXiv 2506.15025 "最优 embedding LR ∝ 1/V"）是误读，原文讲的是 embedding/hidden **比值** ∝ Θ(√width)；250 步选出的 lr 外推到 7000+ 步不可靠；且在产出 headline CI 的同一个 val 上选超参是泄漏。降级为"安全带检查"（见 1.6） |
| 跨文档 block-diagonal mask | 否决，列 future work | MiniMind attention 只接受 2D key-mask（`scores += (1-mask[:,None,None,:])*-1e9`），传非全 1 会关掉 flash SDPA |

### 1.2 数据预处理与落盘格式

产物目录 `lab/data/v3/`。

**D1 `lab/make_val_large.py`** — 验证集扩到 20,000 篇，且**包含**原 1943 篇（保持与 30M 历史结果逐篇可比）
- 选法：对 `lab/data/v2/train.jsonl` 每篇算 `sha256(text)`，按十六进制升序取前 18,057 篇（确定性、可复现），与原 val 的 1943 篇取并集
- 落盘：`val_large.jsonl`（20,000）、`train.jsonl`（1,250,237 篇）、`val_manifest.jsonl`（每行 `{"i":序号,"sha256":...}`，供第三方不下载原文也能重建）、`manifest.json`

**D2 `lab/neardup_audit.py`** — 真正的近重复审计（**不用 Jaccard≥0.8**，它查不出包含式泄漏）
- 对每篇 val 文档取 64 字符窗口、步长 32，算 blake2b-64 → `hash → val_doc_id` 字典（约 30–60 万条）
- 流式过一遍 train.jsonl，同样开窗查表；某 train 文档与某 val 文档共享 ≥3 个不同窗口（≥192 字符重合）即判近重复
- 命中的 val 文档剔除，`manifest.json` 里 `near_duplicate_check` 从 `"not performed"` 改为实际方法与剔除数
- 成本：单遍扫 485M 字符，约 15–25 分钟

**D3 `lab/pack_corpus.py --arm {A,B}`** — 离线打包
```
doc_order = np.random.default_rng(42).permutation(n_docs)   # 两臂共用（CRN）
for doc in doc_order:
    stream += [BOS] + tok(text, add_special_tokens=False).input_ids + [EOS]
切成定长 512，丢弃尾部不足 512 的残段
```
- **绝不在序列边界额外插 EOS**。BOS/EOS 只标记真实文档边界；序列边界是流上的任意切点。
- 落盘：

| 文件 | 内容 |
|---|---|
| `packed_A.ids.u16` | memmap `(n_seq, 512)` uint16 |
| `packed_A.bytes_cum.i64` | `(n_seq,)` int64，第 i 条序列末尾已消费的**精确**原文 UTF-8 字节数（用 `return_offsets_mapping` 取当前文档的字符偏移后再 `.encode('utf8')` 计长，不做按 token 比例的估算） |
| `packed_A.meta.json` | arm / tokenizer_sha256 / vocab_size / n_seq / seq_len / bos_id / eos_id / total_tokens / text_tokens / structural_tokens / total_utf8_bytes / bytes_per_token / ids_sha256 / doc_order_sha256 / dropped_tail_tokens |
| `doc_order.i32` | 两臂共用，带 sha256 |

- **四条硬断言（失败直接崩，不 warning）**：
  1. 前 1000 条序列 `decode(skip_special_tokens=True)` 拼接后，必须与 doc_order 顺序的原文拼接**逐字节相同**
  2. `ids.max() < vocab_size`，且 padding 计数 == 0
  3. `total_tokens` 落在 A ≈ 302M / B ≈ 255M 的 ±1% 内
  4. `bytes_cum` 单调非减，末项 ≤ 语料总字节

**D4 `lab/build_eval_chunks_v3.py`** — 共同文本分块（评测侧）
- 用臂 A 的 tokenizer 定边界，每块 ≤510 个 A-token，**不跨文档**；落 `eval_chunks_v3.jsonl`（`doc, chunk, cs, ce, utf8_bytes`）+ sha256
- 启动时断言 tokenizer 嵌套关系：`merges_A == merges_B[:len(merges_A)]`、A 的 6400 个 token 在 B 中 id 全一致、两者 `BPE(dropout=None, fuse_unk=False, byte_fallback=False, ignore_merges=False)` 与 `ByteLevel(add_prefix_space=false, use_regex=true)` 全同。这四个开关任一不同，`len_B ≤ len_A` 的构造性保证就失效
- 再断言每块的 B-token 数 ≤ 510（复核，不是假设）

### 1.3 Dataset

`lab/packed_dataset.py`：
```python
ids = torch.from_numpy(self.ids[i].astype('int64'))
x, y = ids[:-1], ids[1:]        # 511 个监督目标，全部有效
return x, y, int(self.bytes_delta[i])
```
**不使用** `labels[input_ids == pad_id] = -100`。上游那行在 pad 是 `<|endoftext|>`(id 0) 时会把正文里字面出现的该串误掩码（实测 `tA('前<|endoftext|>后') == [769, 0, 617]`）；packing 后没有 padding，这行本就该删掉。

结构 token（BOS/EOS）**计入监督**，理由：两臂绝对数量相同，是学文档边界的正当信号；不对称仅 0.23 个百分点（占目标 A 1.26% / B 1.49%），不值得为它多跑一组 run。分开记账 `text_targets` / `structural_targets`，并写进限制条款。

### 1.4 训练侧补丁（扩 `lab/upstream-pretrain.patch`）

**(a) 加 warmup。** 上游 `trainer_utils.get_lr = lr*(0.1+0.45*(1+cos(pi*t/T)))`，t=0 就是满 lr，从随机初始化直接上 2e-4。替换为 WSD：
```python
def get_lr(step, total, lr, warmup_frac=0.02, decay_frac=0.10, floor=0.1):
    w, d = max(int(warmup_frac*total),1), max(int(decay_frac*total),1)
    if step < w:         return lr*(step+1)/w
    if step < total-d:   return lr
    p = (step-(total-d))/d
    return lr*(floor+(1-floor)*0.5*(1+math.cos(math.pi*p)))
```
每个 run 的 `total` 等于它**自己**的总步数，独立完整退火。

**(b) 每次 optimizer update 写一行 `run_ledger.jsonl`：**
```
step, seqs_consumed, tokens_cum, targets_cum, text_targets_cum, structural_targets_cum,
positions_cum, utf8_bytes_cum, flops_nominal_cum, wall_seconds_cum,
lr, grad_norm, loss_nats_per_target, train_bits_per_byte
```
- `train_bits_per_byte = loss_mean × n_targets / (ln2 × batch_utf8_bytes)` — 训练期唯一跨臂可比的实时曲线，必须打
- `flops_per_position`：A = 6×(58.997M + 4.915M) + 12×8×768×512 = **421.2M**；B = 6×(51.622M + 12.583M) + 12×7×768×512 = **418.3M**。差 0.71%，方向是 A 更重（实测墙钟差 1.1%）

**(c) 新增 CLI**：`--packed <prefix>`、`--total_tokens`、`--save_steps_frac`、`--ledger`。

### 1.5 训练命令

```bash
python lab/run_pretrain.py \
  --arm A --seed 42 \
  --packed lab/data/v3/packed_A \
  --total_tokens 240e6 \
  --batch_size 64 --accumulation_steps 1 --max_seq_len 512 \
  --learning_rate 2e-4 --schedule wsd --warmup_frac 0.02 --decay_frac 0.10 \
  --grad_clip 1.0 --dtype bf16 \
  --out lab/runs/main-A-s42-T240M --save_steps_frac 0.05
```
两臂唯一的差异只有 `--arm / --packed / vocab_size / num_hidden_layers`。batch 由到机 bench 决定，但**两臂必须同 batch**。

### 1.6 LR 处置

**两臂同用 lr=2e-4，不按臂调。** 与 arXiv 2605.01188 的做法一致，并作为明确局限写进报告。唯一的保险是一次**安全带检查**（不是调参）：2 臂 × {1e-4, 2e-4, 4e-4} × 25M token，在从 train 另切的 1000 篇 **tuning split**（不是 val）上看 BPB。只用于确认 2e-4 对任一臂都不是灾难性选择；若某臂换 lr 能改善 >0.05 BPB 才升级处理。成本约 1 小时 ¥2。

## 二、训练预算

### 2.1 档位

单位：每臂的监督 token 数。tokens/update = 64 × 511 = 32,704。

| 档位 | A 步数 | B 步数 | A 读入原文 | B 读入原文 | 用途 |
|---|---|---|---|---|---|
| R-half（等算力） | 120M / 3,669 | 120M / 3,669 | ≈0.48 GB (40%) | ≈0.57 GB (47%) | 趋势：差距随预算扩大还是缩小 |
| **R-main（等算力，主）** | **240M / 7,338** | **240M / 7,338** | ≈0.96 GB (79%) | ≈1.14 GB (94%) | **主结论** |
| R-byte（等字节，仅 B） | — | ≈203M / 6,207 | — | = A@R-main 的字节数 | 副结论 |

R-byte 的确切 token 数由 `packed_B.bytes_cum` 反查 A@240M 的字节值确定，不用比例估算。两档都在 1 epoch 内，无数据重复。

**每 seed 5 个 run、923M token；4 个 seed（42/43/44/45）= 20 个 run、3.69B token。**

### 2.2 在哪跑、多久、多少钱

- **AutoDL RTX 4090**（ModelScope Notebook 免费 A10 额度作溢出备选）
- 吞吐规划值 40k–70k tok/s（**必须到机 bench，官方价格页是 JS 渲染、抓不到，付款前浏览器自核价格**）
- 纯计算 14.6–25.6 h；含 1.4× 开销（上传、eval、调试、重跑）→ **机时 20–36 h**
- 单价按 ¥2/h 规划（第三方调研 ¥1.98–2.68/h，标 UNVERIFIED-at-source）→ **¥40–72，硬上限 ¥300**
- 墙钟 2–3 天
- 上传策略：本地打包并记录 `ids_sha256`，只上传 `train.jsonl`（压缩后约 400MB）+ 代码，在机上重跑 `pack_corpus.py` 并断言 sha256 相等（既省带宽又是确定性检查）
- 评测成本控制：中途 checkpoint 只在 1943 篇子集上评（约 15s，用于画曲线、标注"未退火、不进结论"）；终点完整退火 checkpoint 才在 20,000 篇上评

### 2.3 这个预算能支撑什么

- **主结论**：在 64M 总参数、相同数据顺序、相同 seed、相同 WSD 日程、**相同算力（等步数 = 等 position = 等墙钟，每 position FLOPs 匹配 0.71%）**下，B 相对 A 的 ΔBPB = x ± 95% CI（两层不确定度：20,000 篇文档级 cluster bootstrap + k=4 的 seed 间方差，df=3）
- **副结论**：等原文字节下的 ΔBPB（B 用独立完整退火的 R-byte run，不是中途 checkpoint）
- **趋势**：120M → 240M 两个各自完整退火的档位，差距是扩大、缩小还是持平
- **机制量化**：相同文本下 B 只需 A 的 84.5% 个 token；等算力下 B 多读 18.4% 原文
- **方法学副产品**：σ̂_d（该规模下两臂配对差值的 seed 间标准差，文献里少见）；packing 把 padding 从 58.9%(A)/64.4%(B) 降到 0，监督 token/秒提升 2.4×/2.8×；v2 评测协议自带的镜像混淆（val 上 A 被迫切 2169 块、B 只需 2087 块，多 3.9% 次上下文重置，集中在占 29.5% val 字节的 143 篇长文）

**达成灵敏度（预注册）**：SE_eval(n=20,000, 两臂均已训练, r=0.95) ≈ 0.00173。k=4 时 MDE(80% 功效) = 4.432 × √(σ_d²/4 + SE_eval²)：

| σ_d | 0.008 | 0.012 | 0.018 |
|---|---|---|---|
| MDE | 0.0193 | 0.0277 | 0.0403 |

即本设计能分辨 |ΔBPB| ≳ 0.02–0.04。**这个数字必须与结论并排印出。**

### 2.4 这个预算不能支撑什么

- 不能宣称收敛区间的结论：R-main 只有 **3.76 token/参数**，Chinchilla 要 20
- 不能外推到更大模型、其他 seq_len、其他语料、其他架构
- 若 |Δ| < MDE，只能写"未能区分（inconclusive）"，并报 CI、MDE 与 σ̂_d，**不得写"无差异"或"等价"**
- 不能宣称种子稳健性超出 k=4 的分辨力

## 六、README 必须写明的诚实边界

1. **这是打包对比（package comparison），不是词表消融。** 两臂同时差三样：词表 6400 vs 16384、层数 8 vs 7、tied embedding 4.915M vs 12.583M 参数。正确表述是"6400词表8层 这一配置 vs 16384词表7层 这一配置"，不是"大词表 vs 小词表"。
2. **预算条件性。** R-main 只有 3.76 token/参数，Chinchilla 比例要 20；全部结论限定在 ≤1 epoch 的欠训练区间，不能外推到充分训练或更大模型。
3. **不得宣称"欠训练不利于大词表臂，所以 B 赢是保守下界"。** 随机初始化的解析 BPB 是 A ≈ ln(6400)/(ln2×4.01) = 3.15、B ≈ ln(16384)/(ln2×4.75) = 2.95 —— B 在零训练时就先赢 0.205 BPB。方向相反的两种力同时存在，量级都不明。
4. **两个 tokenizer 是嵌套的**（6400 的 6108 条 merge 是 16384 的 16092 条的精确前缀，vocab ⊆ 且 id 全一致）。这对内部效度是优势，对外部效度是限制：独立训练的 6400 词表会得到不同的 merge（本项目自己的数据就证明了：官方 MiniMind 6.4K 是 1.4872 字符/token，同源 6.4K 是 1.6061），结论不能直接搬过去。
5. **单一语料、单一 seq_len 512、单一 lr、单一架构；未按臂调 LR**（与 arXiv 2605.01188 相同处理，并明确列为局限）。
6. **只测 BPB。** 无下游任务、无生成质量、无推理时延与显存对比。不能说"B 的模型更好"，只能说"B 的 BPB 更低/更高"。
7. **packing 引入的训练/评测失配**（对两臂近似对称，但影响绝对数值）：训练序列可能从文档中段开始、有跨文档上下文，评测每块从 BOS 开始且不跨文档；RoPE 位置不在文档起点重置；训练对 BOS/EOS 计损失（占目标 A 1.26% / B 1.49%，相对差 0.23pp）而评测不计。
8. **未实现跨文档 block-diagonal mask。** 不能宣称消除了跨文档注意力污染，只能论证它在字节层面对两臂对称（token 位置层面不对称，量级极小）。
9. **近重复审计的方法与剔除数必须公布。** 精确内容哈希重复为 0 不等于语义层面不重叠。
10. **若 |Δ| < 达成的 MDE**，只能写"未能区分"，并与 CI、MDE、σ̂_d 并排印出；**不得写"无差异"或"等价"**。
11. **必须更正项目内/交接文档里的三个旧说法：**
    - "臂 B 在 510 token 窗口下多读 18% 原文"在**当前按篇截断+padding** 协议下是错的，实测只有 **+2.5%**（因为 93–95% 的文档短于 510 token，两臂都完整读完）。+18.4% 只在 packing 之后的等步数口径下成立。
    - 每 position 名义 FLOPs 匹配到 **0.71%**（不是 0.46%，后者只是核心项、漏了注意力项），实测墙钟差 1.1%。
    - 配对 SE 的驱动量是 **NLL 残差相关 r = 0.8458**，不是逐文档 BPB 的 r = 0.7972。
12. **与 arXiv 2605.01188 的关系必须如实写：**它固定每样本 8192 字节、让 token 数与每样本 FLOPs 浮动；本项目固定算力、让字节浮动——**两者在最关键的那根轴上做了相反选择**。且该文结论"最优压缩率随训练预算增大而下降"在本项目这个比它最小预算还低约 40 倍的尺度上，**预测 B 会赢**。这一点必须主动披露，否则结论看起来像被协议选择决定的。
13. **arXiv 2107.02027 (Krell et al.) 的结论方向是"不加 mask 的 packing 会造成 cross-contamination 并损害精度"** —— 引用它时不得当作"不加 mask 也没关系"的支持。
14. **许可部分："这不是法律意见。"** 并写明三条不确定性：(a) HF 与 ModelScope 对 minimind_dataset 的许可声明不一致；(b) 上游 pretrain 文件无逐文件来源标注，原文是"包括但不限于……蒸馏补充语料"，故"我只用了 pretrain 文件所以是 Apache-2.0"**无法证明**；(c) 上游只给了 Magpie-Align 的组织名，无法核实语料是否含 Llama 3 生成文本——若含，Meta Llama 3 社区许可要求显示"Built with Meta Llama 3"且模型名开头带"Llama 3"，本项目未作此标注，因为无法确认适用性。
